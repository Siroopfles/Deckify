| Property | Value |
|----------|-------|
| Tool | none (`@decky/ui` manual SteamOS GamepadUI design system + inline style tokens; no `components.json`) |

> **System Constraints:** Renders inside SteamOS GamepadUI CEF (`1280x800` handheld / `1080p+` docked). The banner is plain DOM (no `toaster.toast`, so no chime). All text is rendered as React text nodes (never `dangerouslySetInnerHTML`). Banner artwork, if shown, must come through the base64 proxy (CSP). Horizontal controller strips MUST use `flow-children="horizontal"` (never `"row"`).

## Color

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | `#121212` | Existing modal/settings surface; banner background at `rgba(18,18,18,0.92)` |
| Secondary (30%) | `#1E1E1E` / `rgba(255,255,255,0.04)–0.08` | Settings chord rows/cards, unbound/inactive chord chips, banner border `rgba(255,255,255,0.12)` |
| Accent (10%) | `#1DB954` | Reserved list below |
| Destructive | `#E53935` | Chord validation rejection message (reserved/duplicate) and failed-action error banner left rule only |

Accent (`#1DB954`) reserved strictly for:
1. Left accent rule (3px) on success banners (`▶ Pinned…`, `♥ Liked…`, `Lyrics HUD On`, track-change) — error banners use `#E53935`, neutral banners (`♡ Removed…`, `Lyrics HUD Off`, `No pinned playlists`) use `rgba(255,255,255,0.35)`.
2. Chord chips of the binding currently being recorded (live captured buttons) and the `Recording…` badge/ring.
3. `silent_banner_enabled` toggle on-state and `focusHalo` controller focus ring (`rgba(29,185,84,0.7)`) on chord rows.
4. `Bound` chord chips in saved state are NOT accent (they use secondary surface + white text).

| Settings toggle | Label `Silent HUD Banner`; description `Show track changes and chord confirmations as a silent in-game banner instead of a Steam toast.` |
| Empty state heading | `Unbound` (chip text for an action with no chord) |
| Empty state body | `Press Record Chord, then hold 1–4 buttons together to bind this action.` |
| Recording prompt | `Hold your button combination… (5s)` — capture commits when all buttons are released after the last press; auto-cancels at 5s with `No buttons detected — recording cancelled.` |
| Error state (validation) | Reserved: `That combination is reserved by Steam. Choose a different one.` Duplicate: `Already used by {Action}. Clear that chord first or choose another.` Over limit: `Chords support up to 4 buttons.` |
| Error state (actions) | Like failure banner: `Couldn't update Liked Songs — try again`; Pinned failure: `Couldn't start pinned playlist`; Lyrics persist failure: `Couldn't save lyrics setting`; Save bindings failure (toast in Settings): `Failed to save chord bindings — try again.` |

Per-action `Clear Chord`/`Reset Chord` are single-step (non-destructive, reversible by re-recording). |

## Visual Hierarchy & Interaction Contract

### 1. `SilentBanner` (new; `TOAST-01`)
- **Mount:** Rendered by `DeckifyOverlayWrapper` as a **sibling outside the `overlay_enabled` / HUD-visibility gate** (wrapper no longer `return null` when overlay disabled). Gated on `silent_banner_enabled` (D-01, D-11), while track-change banner emission inside the `track_metadata` handler is separately gated on `toast_enabled !== false` (D-01) so chord confirmations still display via `SilentBanner` whenever `silent_banner_enabled` is true even when track-change notifications are disabled.
- **Positioning:** `position: fixed`; corner from `overlay_position` / `toast_position` normalized with `replace("_","-")` (D-02): `top-left | top-right | bottom-left | bottom-right`; inset `24px` (lg) from edges. Default `top-right`. Banner never overlaps the HUD: if HUD is visible in the same corner, banner offsets below/above it by `8px` (sm) — otherwise stacks directly at the inset.
- **Box:** `min-width: 240px`, `max-width: min(420px, 40vw)`, padding `12px 16px`, `border-radius: 8px`, background `rgba(18,18,18,0.92)`, border `1px solid rgba(255,255,255,0.12)`, 3px left rule per Color. `z-index` above HUD. `pointerEvents: "none"`, no `tabIndex`, not a `Focusable` (D-05) — never steals controller focus.
- **Timing:** visible `3500ms` (D-03). Fade-in `150ms ease-out`, fade-out `250ms ease-in` inside (not added to) the 3.5s. Latest-wins: new event replaces content immediately (no cross-fade, no queue), resets timer, keyed on event `id`. Respect `prefers-reduced-motion`: opacity only, no translate.
- **Track-change layout:** optional 40px proxied cover (left, `border-radius: 4px`), then two-line text block. Chord banners are single-line, no cover.
- **Fallback:** when `silent_banner_enabled` is false, all notifications use `toaster.toast` (D-11). When `toast_sound_enabled` is true, track-change keeps `toaster.toast` with chime unchanged (D-04). In silent path `toaster.toast` MUST NOT be called.

### 2. Settings: Chord Bindings (`SettingsTab.tsx`; `CHORD-01`)
- **Placement:** new card `In-Game Quick Chords` (`FaGamepad` accent-free header icon, `Heading` 16px) below the existing `gamepad_chords_enabled` toggle, containing `Silent HUD Banner` toggle first, then action rows, then `Reset All Chords`.
- **Action row order (top→bottom, each a `Focusable flow-children="horizontal"`):** Previous Track, Next Track, Play / Pause, Volume Up, Volume Down, Like / Unlike, Cycle Pinned Playlists, Toggle Lyrics HUD.
- **Row anatomy (left→right):** action name (`Heading`) + chord chip strip (`Label` chips, `xs` gap; `Unbound` chip when empty) · `Record Chord` · `Clear Chord` · `Reset Chord`. Each control `minHeight: 44`.
- **Defaults shown:** legacy actions display their `STEAM/QAM + button` combo (guide shown as `STEAM / QAM` single chip); the 3 new actions show `Unbound` (D-08).
- **Recording states:** idle → recording (row gets accent ring, `Recording…` badge, live chips update as buttons go down, prompt text below row) → committed (valid) | rejected (red message below row, binding unchanged). While recording the chord matcher is suppressed and the 5s timeout shows a countdown in the prompt. The `B` button or `Cancel Recording` also cancels. Recording blocks other rows' `Record Chord` buttons (`disabled`).
- **Validation (D-07):** reject Valve reserved (`STEAM/QAM + X / R1 / L1`, GUIDE-normalized), duplicates of another Deckify chord, >4 buttons. Single bare buttons accepted. Rejection message auto-clears after 5s or on next record.
- **Chord disabled state:** when `gamepad_chords_enabled` is false, rows render at `opacity: 0.5` with `Record Chord` disabled and helper `Enable in-game chords above to use these bindings.`
- **Runtime rules surfaced to user:** helper text under card header (`Body`): `Chords work in-game and while the Quick Access Menu is open. They are paused while the Deckify window is open.` (D-10)

### 3. Chord feedback behavior
- Every chord action emits exactly one banner (D-11) via single `notify()`; nothing else visible (no modal, no focus change).
- Like: optimistic banner immediately, error banner on rollback (D-13). Pinned: banner after RPC dispatched (D-12). Lyrics: banner after flip + persist (D-14).
- `guideHeld` auto-expires after 4s with no visual indicator (silent safety guard).
