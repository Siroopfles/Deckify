  <files>py_modules/spotify.py, py_modules/resilience.py, main.py, tests/test_spotify.py</files>
  <behavior>
    - Identical GET requests within the endpoint TTL (e.g. 2.0s for me/player, 15.0s for search/artists/albums/tracks/playlists) return cached responses without hitting urllib.request.urlopen; non-GET mutations (PUT/POST/DELETE) invalidate relevant cache entries.
    - Concurrent identical GET requests coalesce on a single in-flight HTTP request.
    - A sliding-window rate limiter paces outgoing Web API requests when burst rate approaches threshold, and _reset_rate_limit_breaker() resets cache/limiter state cleanly for tests.
    - EventServer.get_poll_interval(plugin) returns >= 10.0s when audio_backend == "spotify_client" or _poll_play_state != "playing", and main.py:_poll_playback skips Web API me/player when breaker is open (without resetting backoff).
  </behavior>
  <action>
    1. In `py_modules/spotify.py`:
       - Add a thread-safe `_GET_CACHE` (`OrderedDict` bounded to 128 entries) keyed by `(endpoint, tuple(sorted((params or {}).items())), token_hash)` with short TTLs (`2.0s` for `me/player`, `15.0s` for `search`, `artists/`, `albums/`, `tracks/`, `playlists/`), invalidated on `PUT`/`POST`/`DELETE` requests.
       - Add in-flight GET deduplication (`_INFLIGHT_GETS`) using `threading.Event` so simultaneous identical GETs wait for the first caller's result/exception instead of issuing duplicate HTTP calls.
       - Add a sliding-window pacer (`_RATE_WINDOW` deque of timestamps, max 25 requests per 10.0s) that sleeps briefly (bounded to 0.5s) before non-cached HTTP calls when bursting, and update `_reset_rate_limit_breaker()` to also clear `_GET_CACHE` and `_RATE_WINDOW`.
       - Cap `_BREAKER_MAX_SECONDS` at `60.0` (instead of `300.0`) so a transient 429 never locks out user actions for 5 minutes.
    2. In `py_modules/resilience.py:EventServer.get_poll_interval`:
       - When `settings.get("audio_backend", "librespot") == "spotify_client"` or `getattr(p, "_poll_play_state", None) != "playing"`, return `15.0` (or `POLL_INTERVAL_RELAXED_S` = `20.0` when paused/idle) instead of `3.0s` (`POLL_INTERVAL_FAST_S`), keeping `3.0s` only when actively playing on `librespot` without a healthy `--onevent` socket or on remote playback.
    3. In `main.py:_poll_playback`:
       - When `self._is_spotify_client_running()` and `_poll_play_state != "playing"`, prefer `_cdp_get_player_state` first to detect local playback start without spending a Web API `me/player` request when idle.
    4. Add unit tests in `tests/test_spotify.py` (create if absent or extend existing) covering GET cache hit/invalidation, in-flight deduplication, 429 breaker cap, and `get_poll_interval` backoff for `spotify_client` and paused states.
  </action>

| Spotify Web API responses → `_GET_CACHE` / `_RADIO_CACHE` | Cached API payloads shared across callers within the plugin process |

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |

| T-26-18 | Information Disclosure | `py_modules/spotify.py:_GET_CACHE` | medium | mitigate | Key `_GET_CACHE` by a SHA-256 hash of `token` (never raw bearer token) and bound cache size to 128 entries with short TTLs (`2s`–`15s`). |
| T-26-19 | Denial of Service | `py_modules/rpc_playback.py:start_radio` | medium | mitigate | Propagate `SpotifyRateLimitError` immediately out of Tier 3 and cap `_RADIO_CACHE` at 32 entries so 429s never cause retry storms or memory growth. |
