## Component Layout & Interaction Contract (`SettingsTab.tsx`)

### 1. "Docked Audio-Switching" Card Placement
Placed directly adjacent to the existing `"Audio Output Sink (PipeWire)"` card in `SettingsTab.tsx` inside `<div style={{ marginBottom: 20, padding: 14, borderRadius: 10, background: "rgba(255,255,255,0.04)" }}>`:

- **Header row (`display: "flex", justifyContent: "space-between", alignItems: "center", marginBottom: 8`):**
  - Left: `<h3 style={{ fontSize: 14, fontWeight: 700, color: "#1db954", display: "flex", alignItems: "center", gap: 8 }}>` `Docked Audio-Switching` `</h3>`
  - Right: Live status badge (`fontSize: 12, fontWeight: 700`):
    - When `dock_auto_switch_enabled === false`: `Disabled` (`opacity: 0.6`)
    - When docked & actively routed to dock sink: `Docked: {activeSinkLabel}` (`color: "#1db954"`)
    - When docked & held for Bluetooth (`bluez_output.*`): `Bluetooth Held` (`opacity: 0.8`)
    - When docked & user manually overrode sink: `Manual Override` (`opacity: 0.8`)
    - When enabled & no dock sink connected: `Monitoring` (`opacity: 0.7`)

### 2. Core Toggles (`ToggleField` stack)
Inside `<Focusable flow-children="column" style={{ display: "flex", flexDirection: "column", gap: 4, marginBottom: 16 }}>`:
1. **Auto-Switch on Dock** (`dock_auto_switch_enabled`, default `false`):
   - Description: `Automatically route Deckify to a USB-DAC or HDMI sink on startup and hotplug (with Bit-Perfect Clock).`
2. **Respect Bluetooth Headphones** (`dock_respect_bluetooth`, default `true`):
   - Description: `Keep audio on active Bluetooth headphones when docking; switches to dock if Bluetooth disconnects.`
3. **Pause on Undock** (`dock_pause_on_undock`, default `false`):
   - Description: `Pause Spotify playback automatically when the designated dock or DAC is disconnected.`
4. **Dock Switch Toasts** (`dock_toast_enabled`, default `true`):
   - Description: `Show a brief notification when Deckify switches audio sinks on dock or undock.`

### 3. Target Sink Selector (`InteractiveRow` list)
Sub-heading (`fontSize: 12, fontWeight: 700, opacity: 0.8, marginBottom: 8`): `Target Dock / DAC Sink`
Inside `<Focusable flow-children="column" style={{ display: "flex", flexDirection: "column", gap: 4 }}>`:
1. **First row (always present):** `Auto (USB-DAC / HDMI)` (`id: "auto"`)
   - Left: `Auto (USB-DAC / HDMI)` (`fontSize: 12, fontWeight: 700`)
   - Right: `USB-DAC > HDMI` hint (`fontSize: 12, opacity: 0.6`) + `Active` (`color: "#1db954"`) when selected.
2. **Detected PipeWire sinks (`audioSinks`):**
   - Each sink renders an `InteractiveRow` with `active={dockTargetSink === s.name}` and `style={{ justifyContent: "space-between" }}`.
   - Selecting any row calls `backendSetSetting("dock_target_sink", targetId)`, updates local state optimistically, and shows toast `Dock target: {targetLabel}`.
3. **Empty external sink state:**
   - When `audioSinks` contains no USB-DAC or HDMI sinks, render the `Empty state heading` and `Empty state body` below the `Auto (USB-DAC / HDMI)` row (`opacity: 0.7`) so users understand hotplug monitoring still works.

### 4. Manual Sink Override & Event Sync
- Selecting a sink in the sibling `"Audio Output Sink (PipeWire)"` card while docked triggers backend manual-override protection (`D-06`), updating the status badge to `Manual Override` until the dock sink is disconnected and reconnected.
- Frontend listens to `dock_audio_switched` backend event to refresh `dock_status` (header badge) and display the `showToast` notification when `dock_toast_enabled` is `true`.

## UI Considerations

Applicable state considerations resolved: 6 covered, 0 backstop, 0 unresolved.

| Category | Element(s) | Status | Resolution / Reason |
|----------|------------|--------|---------------------|
| Spatial D-pad navigation | Target Sink `InteractiveRow` list & `ToggleField` stack | ✅ covered | All toggles and sink rows are stacked vertically inside `<Focusable flow-children="column">` so D-pad Up/Down moves cleanly without focus traps or vertical jumps. |
| Empty external sink state | Target Sink selector when no USB-DAC/HDMI sink is connected | ✅ covered | `Auto (USB-DAC / HDMI)` remains selectable at all times and displays the documented empty-state guidance copy below it when no external dock/DAC sinks are present. |
| Bluetooth & manual override states | Header live status badge | ✅ covered | Displays distinct `Bluetooth Held` and `Manual Override` states so users know why Deckify did not hijack their headphones or manual sink choice while docked. |
| Compact QAM constraint | Quick Access Menu (`src/index.tsx`) | ✅ covered | QAM remains untouched with zero dock-switching controls; all controls live exclusively in `SettingsTab.tsx`. |
| Long sink descriptions | `InteractiveRow` sink label | ✅ covered | Sink labels use `minWidth: 0` with `overflow: "hidden", textOverflow: "ellipsis", whiteSpace: "nowrap"` so long USB-DAC / HDMI ALSA descriptions never push the `Active` badge off-screen. |
| Error / fallback state | Dock switch failure | ✅ covered | If `set_audio_sink` fails during hotplug, backend preserves current routing and surfaces the documented error toast (`Dock audio switch failed — kept current audio output. Check PipeWire sinks in Settings.`). |
