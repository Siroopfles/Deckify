## Architecture Patterns

### Pattern 1: Parallel 3s Exit Debounce Without Double-Waiting
**What:** Keep `await backendHandleAppLifetimeEvent(appId, false)` at `src/index.tsx:1134` so `SoundtrackManager.handle_app_lifecycle(valid_id, False)` starts its own `3.0`s `_delayed_exit` immediately, while gating `main.py:736` so `handle_app_lifetime_event` only invokes `self.trigger_ducking(True, "game", valid_id)` when `running` is `True`:
```python
# Source: main.py:735-738 (proposed fix)
override = manager.ducking_override(valid_id)
if override is not False and running:
    await self.trigger_ducking(True, "game", valid_id)
await manager.handle_app_lifecycle(valid_id, running)
```
**Why this over moving `backendHandleAppLifetimeEvent(appId, false)` inside `gameExitDebounceTimer`:**
- Moving `backendHandleAppLifetimeEvent(appId, false)` inside `src/index.tsx`'s `3000`ms `gameExitDebounceTimer` would stack two 3-second timers (`3000ms` frontend + `3.0s` `soundtrack_exit_debounce` in `py_modules/soundtrack.py:270`), delaying soundtrack restoration to **6.0 seconds**.
- Gating `main.py:736` on `and running` preserves:
  - Immediate game ducking on `bRunning: true` (when `ducking_override` is not `False`) — preserving `tests/test_soundtrack.py:312-327` (`test_lifecycle_event_routes_and_ducks`, `test_ducking_override_false_skips_duck`).
  - `VolumeFader.set_ducking(False, reason="game")` (`py_modules/volume.py:255-260`) idempotently discards `"game"` from `self._duck_reasons` after `3000`ms when `gameExitDebounceTimer` fires `backendTriggerDucking(false, "game")` (`src/index.tsx:1139`).
  - Proton/launcher flapping (`bRunning: false` followed by `bRunning: true` within 3000ms) cancels both `gameExitDebounceTimer` (`src/index.tsx:1125-1128`) and `SoundtrackManager._exit_task` (`py_modules/soundtrack.py:248`), with zero premature unducking.

### Pattern 2: Full Modal Suppression (`L1`/`R1`/`X`/`Y` + `L2`/`R2`) via `useTriggerNavigation` & `onPickerOpenChange`
**What:**
1. In `src/hooks/useTriggerNavigation.ts:62-70`, `dispatchAction` currently checks:
   ```ts
   // Source: src/hooks/useTriggerNavigation.ts:62-63
   const dispatchAction = (action: ModalButtonAction, e?: any) => {
     if (!active || !enabledRef.current || isTextInputFocused()) return;
   ```
   Update line 63 to also check `suppressedRef.current`:
   ```ts
   if (!active || !enabledRef.current || suppressedRef.current || isTextInputFocused()) return;
   ```
   Without this, setting `suppressed = true` in `DeckifyExpandedModal.tsx:712` only suppresses `L2`/`R2` (`isTriggerActive()` at line 60) and leaves `L1`/`R1` tab cycling (`onAction`) active underneath any sub-modal (`TrackActionModal`, `CollectionActionModal`, `AddToPlaylistModal`, and `PlaylistPickerModal`).
2. In `src/components/DeckifyExpandedModal.tsx`:
   - Add `const [playlistPickerOpen, setPlaylistPickerOpen] = useState(false);` alongside `actionTrack`, `actionCollection`, and `showAddToPlaylistModal` (`DeckifyExpandedModal.tsx:113-115`).
   - Include `playlistPickerOpen` in `suppressed` at `DeckifyExpandedModal.tsx:712`:
     ```ts
     suppressed: Boolean(actionTrack || showAddToPlaylistModal || actionCollection || playlistPickerOpen),
     ```
   - Pass `onPickerOpenChange={setPlaylistPickerOpen}` to `<SoundtracksTab showToast={showToast} onPickerOpenChange={setPlaylistPickerOpen} />` at `DeckifyExpandedModal.tsx:1188`.
   - Also reset `setPlaylistPickerOpen(false)` in `handleSelectMode` (`DeckifyExpandedModal.tsx:689-699`) for consistency with `setActionTrack(null)` / `setActionCollection(null)` / `setShowAddToPlaylistModal(false)`.
3. In `src/components/tabs/SoundtracksTab.tsx`:
   - Add optional `onPickerOpenChange?: (open: boolean) => void;` to `SoundtracksTabProps` (`SoundtracksTab.tsx:49-54`).
   - In `openPlaylistPicker` (`SoundtracksTab.tsx:127-144`), call `onPickerOpenChange?.(true)` before `showModal(...)` and pass `onClose={() => onPickerOpenChange?.(false)}` to `<PlaylistPickerModal ... />`.
   - Include `onPickerOpenChange` in `openPlaylistPicker`'s `useCallback` dependency array (`SoundtracksTab.tsx:143`) and call `onPickerOpenChange?.(false)` in the unmount cleanup (`SoundtracksTab.tsx:90-95`) so suppression never leaks if `SoundtracksTab` unmounts while the picker is open.

### Anti-Patterns to Avoid
- **Moving `backendHandleAppLifetimeEvent(appId, false)` inside `gameExitDebounceTimer`:** Causes 6.0s stacked exit debounce (`3000ms` JS + `3.0s` Python `soundtrack_exit_debounce`).
- **Only passing `onPickerOpenChange` without fixing `dispatchAction` in `useTriggerNavigation.ts:63`:** Would still leave `L1`/`R1` active because `dispatchAction` ignores `suppressedRef.current`!
- **Calling `handleClose` only on `onSelect`:** `PlaylistPickerModal.tsx:103-106` routes both `onSelect` (`handlePick`) and `ModalRootAny` `onCancel` / Close button through `handleClose`, which calls `closeModal?.(); onClose?.();` — so `onClose` on `<PlaylistPickerModal>` covers all three exit paths (select, B-button cancel, Close button).

## Common Pitfalls

### Pitfall 1: Missing `suppressedRef.current` in `useTriggerNavigation.ts:dispatchAction`
**What goes wrong:** Setting `suppressed: true` on `useTriggerNavigation` stops `L2`/`R2` (`isTriggerActive()`), but `L1`/`R1`/`X`/`Y` (`dispatchAction()`) continue firing `onAction`!
**Why it happens:** `useTriggerNavigation.ts:60` checks `!suppressedRef.current` in `isTriggerActive()`, whereas `useTriggerNavigation.ts:63` in `dispatchAction` only checks `if (!active || !enabledRef.current || isTextInputFocused()) return;`.
**How to avoid:** Add `suppressedRef.current` to the guard in `dispatchAction` (`src/hooks/useTriggerNavigation.ts:63`) and add a Vitest unit test in `DeckifyExpandedModal.test.tsx` asserting `onAction` (`L1`/`R1`/`X`/`Y`) is NOT called when `suppressed: true`.

### Pitfall 2: Stale line 84 in `07-VERIFICATION.md`
**What goes wrong:** Updating only lines 54 and 77 of `07-VERIFICATION.md` leaves line 84 (`**Score:** 17/18 truths verified (1 failed, 0 behavior-unverified)`) inconsistent with frontmatter (`score: 18/18 must-haves verified`).
**How to avoid:** Update all three stale body lines in `07-VERIFICATION.md`: line 54 (`**Status:** passed`), line 77 (`✓ VERIFIED` with `432/432 OK` evidence), and line 84 (`**Score:** 18/18 truths verified (0 failed, 0 behavior-unverified)`).

### Pitfall 3: `SoundtracksTab.test.tsx` `useCallback` / `useEffect` mock behavior
**What goes wrong:** `SoundtracksTab.test.tsx` mocks React hooks (`useState`, `useRef`, `useEffect`, `useCallback`) directly in Vitest without DOM mounting.
**How to avoid:** Verify `SoundtracksTab.test.tsx` passes `onPickerOpenChange` as an optional prop (preserving all 8 existing tests) and test `onPickerOpenChange(true)` / `onPickerOpenChange(false)` via `addBtn.props.onClick()` and `modalElement.props.onClose()`.
