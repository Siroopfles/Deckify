<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Frontend Settings → Backend `settings.json` | Untrusted/malformed `pinned_playlists` payloads cross RPC into `main.py:set_setting` and `py_modules/common.py:_load_settings` |
| Spotify CDN URL → Steam CEF Renderer | External `image_url` strings rendered in QAM could violate Steam CEF CSP or leak requests if not proxied |
| QAM Click → Local Engine Process | `quick_play_pinned` wakes local `librespot` subprocess and polls Spotify Connect API |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-09-01 | Tampering | `py_modules/common.py`, `main.py` | medium | mitigate | Validate `pinned_playlists` is a `list` of `dict`s with non-empty `uri`/`name`, `type` allowlisted to `("playlist", "album", "liked_songs")`, deduplicated, and capped at `MAX_PINNED_PLAYLISTS = 4` (ASVS V5). |
| T-09-02 | Information Disclosure | `src/index.tsx` | medium | mitigate | Render all pinned item thumbnails exclusively through `<DeckifyImage>` backed by `py_modules/images.py` base64 proxy + domain allowlist; never render raw external `<img src>` URLs. |
| T-09-03 | Denial of Service | `py_modules/rpc_playback.py` | low | mitigate | Cap Connect device wake polling in `quick_play_pinned` to 4 attempts × 300ms (1.2s max) to prevent unbounded API polling or event-loop blocking. |
| T-09-SC | Tampering | npm/pip/cargo installs | high | mitigate | No new external packages introduced in Phase 9; uses existing in-repo dependencies only. |
</threat_model>
