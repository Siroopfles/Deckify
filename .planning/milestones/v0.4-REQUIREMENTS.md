# Requirements Archive: Milestone v0.4

**Shipped:** 2026-11-12  
**Milestone:** v0.4 Stability, Polish & Refactoring  
**Core Value:** Rock-solid Spotify playback and responsive, reliable controller navigation on Steam Deck without UI lag, broken images, or desynchronized playback states.  

---

## Shipped Requirements

### Architecture & Refactoring
- [x] **ARCH-01**: Refactor monolithic `DeckifyExpandedModal.tsx` (~2,959 LOC) into clean, modular components under `src/components/tabs/` and `src/components/common/` while preserving full feature parity and zero regression in test suites.
  - *Outcome:* Satisfied in Phase 01. Modal broken down into 12 standalone tab components and 5 shared UI primitives.
- [x] **ARCH-02**: Refactor monolithic `main.py` (~2,600 LOC) into focused backend modules under `py_modules/` (separating RPC routing, volume management, process supervision, and image fetching) while keeping all unit tests passing.
  - *Outcome:* Satisfied in Phase 01. `main.py` decomposed into `volume.py`, `system.py`, `rpc_playback.py`, `rpc_library.py`, `images.py`, `engine.py`, `device.py`, and `common.py`.

### Media & Artwork (CEF CSP Compatibility)
- [x] **IMG-01**: Expand image URL validation and proxying in `py_modules/images.py` to support all Spotify CDN variants (`image-cdn-ak.spotifycdn.com`, `mosaic.scdn.co`, `seeded-session-images.scdn.co`) and podcast cover hosts.
  - *Outcome:* Satisfied in Phase 02. CDN whitelist expanded with mosaic URI normalization.
- [x] **IMG-02**: Add concurrency throttling (max 4-6 concurrent fetches) and an in-memory cache to `DeckifyImage` to eliminate RPC threadpool starvation and prevent Spotify HTTP 429 rate limit backoffs.
  - *Outcome:* Satisfied in Phase 02. `ImageLruCache` (200 items) and `ImageRequestQueue` (concurrency 4) implemented.

### Playback & Time Synchronization
- [x] **PLAY-01**: Implement smooth real-time Now Playing elapsed time ticker interpolated with local clock timestamps (`Date.now()`) so progress counts up seamlessly every second without freezing or jitter.
  - *Outcome:* Satisfied in Phase 03. `usePlaybackClock` built with 250ms monotonic interpolation and 1200ms drift gating.
- [x] **PLAY-02**: Enable gamepad D-pad and controller scrubbing on the Now Playing seek bar using `@decky/ui` focusable controls, allowing stepping forward/backward in track position.
  - *Outcome:* Satisfied in Phase 03. Focusable seekbar thumb with focus halo and 300ms debounced seek commitment.
- [x] **PLAY-03**: Bind Now Playing progress bar and time labels to the live interpolated position state rather than stale backend polling snapshots.
  - *Outcome:* Satisfied in Phase 03. Live position state bound directly to time label and progress bar width.

### Queue Management
- [x] **QUEUE-01**: Fix track selection in the Queue view so clicking/selecting any queue item starts playback of that exact track.
  - *Outcome:* Satisfied in Phase 04. Queue row click bound to `play_tracks` with explicit sliced URIs sequence.
- [x] **QUEUE-02**: Ensure selecting a queue track immediately updates the Now Playing view and re-synchronizes the upcoming queue list in real time.
  - *Outcome:* Satisfied in Phase 04. Optimistic state mutation, dedicated Now Playing card, 40-item rendering cap, and 600ms delayed background resynchronization.

### In-Game HUD Overlay
- [x] **HUD-01**: Ensure the Deckify in-game HUD overlay mounts reliably in Steam GamepadUI gamescope, respects the settings toggle, and auto-hides or displays according to configuration.
  - *Outcome:* Satisfied in Phase 05. Mounted globally in Gamescope with strict `pointerEvents: "none"`, 4 corner placements, direct QAM controls, and 6s auto-hide.
- [x] **HUD-02**: Correctly resolve and render album artwork and playback state indicators (playing/paused) in the HUD overlay.
  - *Outcome:* Satisfied in Phase 05. Rendered via `DeckifyImage`, 3.5s pause grace period, and optional 2px live progress bar.
